# Investigacion: Git y GitHub 
 
## 1. ¨Que es una rama (branch) en Git y para que‚ se utiliza? 
Una **rama** es una linea de desarrollo independiente que parte de un commit. Sirve para trabajar nuevas funciones o correcciones sin afectar la rama principal hasta que esten listas. 
## 2. Explica con tus palabras que significa hacer un merge. 
El **merge** es el proceso de unir los cambios de una rama secundaria (por ejemplo, nueva-funcionalidad) hacia la rama principal (main), integrando todo en un mismo historial. 
 
## 3. ¨Que es un conflicto de fusion (merge conflict) y como se puede resolver? 
Un **conflicto de fusi¢n** ocurre cuando dos ramas modifican las mismas lineas de un archivo o partes incompatibles. Se resuelve editando el archivo manualmente, eligiendo o combinando los cambios, y luego confirmando con git add y git commit. 
 
## 4. Diferencia entre fork y clone en GitHub. 
- **Fork**: copia remota de un repositorio en tu cuenta de GitHub para proponer cambios sin afectar el original. 
- **Clone**: copia local de un repositorio remoto (sea original o fork) para trabajar en tu PC con Git. 
 
## 5. ¨Que es un pull request y para que se usa en proyectos colaborativos? 
Un **Pull Request (PR)** es una solicitud para integrar cambios hechos en una rama o en un fork hacia el repositorio original. Permite que otros revisen, comenten y aprueben antes de fusionar. 
 
## 6. Investiga y explica 3 buenas practicas para colaborar en equipo usando GitHub. 
1. Crear ramas con nombres claros y especificos para cada tarea (ej: feat/login, fix/bug-23). 
2. Hacer commits pequeños y con mensajes descriptivos para facilitar la revision. 
3. Usar pull requests con buena documentacion, checklist y responder a los comentarios de revision.
